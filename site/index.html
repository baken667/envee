envee

Per-directory environment variables, declared in TOML. Entering a project directory loads its environment — without running its code.

brew install baken667/tap/envee
eval "$(envee init zsh)"   # or bash / fish

Why not just use .envrc?

Because a .envrc is a shell script. Loading one means executing whatever is in it, so approving a project directory is approving arbitrary code — including whatever lands there in the next git pull.

An envee.toml is data. Values never become commands, and that property is tested by round-tripping generated output through real shells.

A config

schema = "envee/v1"
profile = "dev"

[env]
SERVICE_NAME = "myapp"
DATABASE_URL = "postgres://localhost:5432/mydb_dev"
LOG_PATH = "{{config_root}}/logs/{{profile}}.log"

# Pulled from a plugin, never written down here.
DATABASE_PASSWORD = { source = "env", ref = "DB_PASS", redact = true }

# Load a .env, prepend to PATH.
_.file = [ { path = ".env", required = false } ]
_.path = [ "./node_modules/.bin" ]

[profiles.prod]
DATABASE_URL = "postgres://prod-host/mydb"
required = [ "DATABASE_PASSWORD" ]

Approve once, explicitly

envee check      # static analysis — runs nothing
envee trust      # shows what the config does, then asks

Trust is bound to the file's content hash, so an edit revokes it until you look again. Every file that contributes counts — envee.local.toml and envee.d/*.toml included.

Profiles

dev / staging / prod as a first-class concept, with per-profile required variables.

Secrets via plugins

Any executable named envee-plugin-<name>. Values marked redact stay hidden in output.

Shareable approval

One reviewer signs an approval with an ed25519 key; colleagues import it verified instead of re-reviewing.

Signed releases

Keyless Sigstore signatures and an SBOM per archive. No key to trust, no key to leak.

Install

# Homebrew
brew install baken667/tap/envee

# Go
go install github.com/baken667/envee/cmd/envee@latest

# Or a signed archive, .deb, .rpm or .apk from the releases page.

Pre-1.0: the CLI surface may still shift between minor versions. bash, zsh, fish, nushell and PowerShell are supported.
