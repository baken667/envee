# ADR-019: Язык реализации — Zig (переписывание с Go)

- **Статус**: Accepted
- **Дата**: 2026-09-09
- **Заменяет**: ADR-0001 (Go)
- **Решает**: На каком языке живёт envee дальше и что при этом теряется

## Контекст

ADR-0001 выбрал Go ради скорости разработки MVP и зрелой инфраструктуры и
оговорил условие пересмотра: если горячий путь (`eval` на каждом
приглашении оболочки) окажется дороже бюджета, переписать его на язык без GC.
После 0.3.0 hook почти не вызывает envee (стамп на shell-builtins), так что
латентность перестала быть аргументом сама по себе. Аргументы, которые
остались:

- **Владелец учит Zig** и хочет проект, на котором это делать всерьёз. Это
  честная причина, и она названа первой.
- **Один статический бинарь без runtime.** Go-бинарь envee — 6 МБ,
  Zig-бинарь — около 1 МБ (ReleaseSafe, strip). Для инструмента, который
  ставят на каждую машину и зовут из hook'а, размер и старт имеют значение.
- **Кросс-компиляция встроена.** `zig build release` собирает linux (musl,
  статически), macOS и windows из любой машины без goreleaser, cgo и
  внешних toolchain'ов.
- **Ноль зависимостей.** Go-версия тянула cobra, BurntSushi/toml, xdg,
  x/crypto/ssh, yaml.v3. В Zig-версии всё, включая TOML-парсер и разбор
  OpenSSH-ключей, написано на std.

## Решение

**Zig 0.16** для envee и `envee-plugin-env`. Go-реализация удалена целиком;
поведение перенесено 1:1 там, где Go был прав, и исправлено там, где нет
(см. «Найдено в Go» в `docs/zig-rewrite-steps.md`). Go-версия служила
эталоном на всём протяжении переписывания: `scripts/parity.sh` сверял вывод
двух бинарей команда за командой (89 проверок на момент удаления Go), а
ожидаемые расхождения — исправленные баги — были оформлены утверждениями.

### Что сохранилось

- Формат `envee.toml`, профили, директивы, шаблоны — без изменений.
- Протокол плагинов (ADR-0007) — побайтно: Go-плагины работают с Zig-ядром,
  и наоборот; `pkg/sdk-go` остаётся поддерживаемым SDK.
- Формат хранилища доверия и подписи ed25519 — записи взаимно читаются;
  подпись, сделанная одной реализацией, проверяется другой.
- Тексты ошибок, коды E001–E015 и коды выхода (ADR-0017).
- Hook'и оболочек (ADR-0005) — байт в байт.

### Что потеряно и чем заменено

| Было в Go | В Zig | Замена |
|---|---|---|
| cobra | свой разбор аргументов (`src/cli/args.zig`) | справка и completion генерируются из того же дерева команд; команда `help` отсутствует, флаги в справке идут в порядке объявления |
| goreleaser | `zig build release` + `release.yml` | архивы, `checksums.txt`, keyless cosign, формула Homebrew — те же артефакты, собранные скриптом |
| `x/crypto/ssh` | `src/trust/ssh_key.zig` | только незашифрованные ed25519-ключи OpenSSH; RSA и ключи с парольной фразой — внятный отказ (E013) |
| `yaml.v3` в `_.file` | нет | dotenv, json, toml; yaml — ошибка с подсказкой. Ни один пример и ни один тест yaml не использовали |
| `enveed` (демон, ADR-0008) | не собирается | `envee daemon status` остался; hook 0.3.0 сделал демон почти бесполезным, и его судьба — отдельное решение |
| BurntSushi/toml | `src/toml/` | свой парсер; каноническое представление изменилось — см. ADR-0020 |
| man-страницы | нет | `envee <cmd> --help`; man — при первом запросе |

### Что изменилось для пользователя

- **Повторный `envee trust` на каждый проект** после обновления: хеш
  считается по новому каноническому виду (ADR-0020), старые записи
  становятся «неизвестными».
- `envee version` печатает `zig 0.16.0` вместо версии Go.
- Бинарь для Linux статический (musl) и не зависит от glibc.

## Альтернативы

- **Rust**, как предполагал ADR-0001 для горячего пути. Отвергнуто: цель
  переписывания — выучить Zig, а не оптимизировать; и Rust-порт только
  горячего пути оставил бы два языка в одном бинаре.
- **Оставить Go и переписать только `internal/shell` и `internal/env`.**
  Отвергнуто по той же причине и потому, что после 0.3.0 горячий путь в
  envee не заходит.
- **Zig с зависимостями** (`zig-toml`, `zig-clap`). Отвергнуто на шаге 10:
  своя реализация оказалась дешевле, чем подстройка под чужую, и даёт
  контроль над каноническим видом.

## Последствия

### Положительные

- Бинарь ~1 МБ, статический, без GC и runtime.
- Одна команда собирает все цели релиза; CI не зависит от goreleaser.
- Ноль внешних зависимостей: нет `go.sum`, нет dependabot по модулям.
- По ходу порта найдено и исправлено шесть ошибок Go-версии (приоритет
  конфигов, `required` до профиля, `-v`, дублирование PATH, циклы `{{env.A}}`
  в `check`, профиль в `resolve`/`diff`).

### Отрицательные

- Zig 0.16 — язык до 1.0; std меняется от версии к версии, и сборка
  привязана к точной версии компилятора (`minimum_zig_version` в
  `build.zig.zon`, `mlugg/setup-zig` с `version: 0.16.0` в CI).
- Меньше людей, способных делать ревью.
- Windows собирается, но не тестируется (experimental).
- Демон и man-страницы выпали из поставки.

### Нейтральные

- `pkg/sdk-go` живёт в подкаталоге со своим `go.mod`: SDK для авторов
  плагинов на Go остаётся, ядро на Go — нет.

## Заметки для будущих ревизий

- Пересмотреть при выходе Zig 1.0 или при смене std так, что порт на новую
  версию дороже недели.
- Если понадобится демон — отдельный ADR: он либо на Zig с `std.Io`
  event loop, либо не нужен вовсе.
